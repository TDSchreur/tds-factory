### Exit checklist

Run these steps in order after the last Ticket, before `run sync`, and again after every Rework, before you commit it. They are inline work in the Run worktree: they create no subagent, do not call `code-review` and record nothing with `run verdict`. Check still owns the review.

1. **Static checks.** Run every check CI runs that you can run here: the project's lint, typecheck and format-check commands (its `package.json` scripts or its conventions file, for example `npm run lint`, `npm run typecheck` and `npm run format:check`), plus a linter for each kind of file the diff changes, such as `shellcheck` for a shell script. The Verify command often does not run them, but CI does, so fix every failure now and run them again. List a check that cannot run here under "Not run" in `build.md`. A project with none skips this step.
2. **Term sweep.** Run `tds-factory run sweep --id <id>`, which lists every place in the README, `docs/`, the Specs, the ADRs, `GLOSSARY.md`, the Skills and the agents that still holds a term the diff changed, and add each older or other wording of a changed term with `--term` (for example "defaults to claude" for a changed default). Read every hit; make each one in a current document say the same thing in one wording, and compare the wordings when a sentence lives in more than one place. A hit marked as replaced is history and needs no change. The sweep also finds a number with a unit or a heading that only the removed lines held, and has a "lists" section: lines in current documents that hold the siblings of a member the diff added to a list but not that member, or that still hold a removed one. For every member you add to or remove from a list yourself, find the sibling members and update every list that holds them, including lists the sweep cannot see (plain words, tables, code). A moved section needs its pointers fixed, and a changed cap or number needs every statement of it fixed.
3. **Required artifacts.** A changelog fragment in `changelog.d/` under the right heading, `GLOSSARY.md` updated with its Avoid terms respected, the canonical spec for the changed area, and a pointer between ADRs where one supersedes or extends another.
4. **Story trace.** In `build.md`, a table with a row for each Spec story and the test that proves it. Close a story that has no test, or name it under "Left open".
5. **Security check.** In `build.md`, list each trust boundary the diff touches (external input, the working folder or environment of a subprocess, config, deleting or overwriting user data, a path that fails open) and how it is handled. Check each one against the project's "Universal safeguards" text from the conventions file when it has one.
6. **Hostile input.** For each parser, matcher or function that handles a path, glob, regular expression, link or other untrusted text in the diff, write an adversarial test: very long input, deep nesting, many repeats, a symlink, `..`, an absolute path, a control character or newline in a name, and a time or size bound on the work when it claims one. Run `tds-factory run sweep` and look at its "claims" section: every "linear", "bounded", "safe", "sanitized" or `O(...)` claim in a comment, document or ADR needs such a test, or the claim goes. Do not hand-roll a security-sensitive primitive the platform or a dependency offers unless Define named that choice and its required adversarial test. A diff without such a function skips this step. It applies again after every Rework: a fix is new code, and "no further findings" is not evidence.
7. **Self-check.** Read `git diff <base_sha>...HEAD` once, against the Standards, Spec and Security lenses that Check applies, and look for what Check usually finds: a current document, a number, a list or a section pointer made stale; a symlink or a path outside the folder that is followed or written; a control character in output; a cap or limit stated in a document that the code does not enforce, or enforced and not stated; a silent drop where the code should fail; one commit for more than one Ticket. Fix what you find and name what you leave under "Left open" in `build.md`. One pass only; after a Rework, read the rework diff.

On the Fast track `build.md` is three lines (what was built, the Verify result, what is left open). The story trace and the security check are written only when the diff touches a trust boundary; the static checks, the term sweep, the required artifacts, the hostile-input step (when the diff has such a function) and the self-check still run.

### After a Rework

A Rework is not only the listed findings. Before you commit it, run the term sweep again and read the rework diff for new surface area, because a fix often opens the next finding. Fix the cheap LOW findings in the area you are reworking instead of leaving them, since a LOW left alone tends to return as a MEDIUM. Name a LOW you leave, with the reason, under "Left open" in `build.md`. Then run the rest of the Exit checklist, verify and return to Check.
