# Progress commands

Read this when you need the exact form or the rules of a `tds-factory run` command. Each command checks its prerequisites and refuses with a message saying what is missing; fix that, never work around it.

- `tds-factory run transition --id <id> --to build|check|finish|follow-up` moves to the next Stage, in order. Add `--data '{"activity":"..."}'` to set the activity line. Build needs the Spec link and Tickets (exactly one Ticket on the Fast track), Check needs every Ticket done, Finish needs a clean or accepted Check (see Check). Finish also needs a branch that merges cleanly into the fetched default branch of `origin`; when it does not, run `tds-factory run sync`, resolve the conflicts and review again. Build, Check and Finish also need a usable Verify command, and `run verify` refuses without one.
- `tds-factory run track --id <id> --value fast|full` records the Track in Define. Run it only after the user named the track, or confirmed Define's recommendation; never on your own judgment (see Tracks).
- `tds-factory run verify --id <id> --fast` runs the fast Verify command of the Run (`fast_commands`) in the Run worktree for quick feedback and prints its result; it records nothing and is never Evidence; it only adds Event log entries. It refuses when the Run has no fast command.
- `tds-factory run verify --id <id>` runs the verify command in the Run worktree and records the Verify result: command, head commit, whether the worktree had uncommitted changes, exit code, times and `verify.log` in the Run folder.
- `tds-factory run config --id <id>` prints the project settings frozen at start: `models`, `max_check_loops` (at most 4, enforced by `run rework` and `run follow-up`) and `labels`. Use `labels.ticket` instead of `ready-for-agent` when you cut Tickets.
- `tds-factory run reviews --id <id>` prints the frozen project review plan and current applicability against the Run base. `tds-factory run materialize-review --id <id> --axis <axis>` writes the frozen Skill and bundled files to a new private Run folder and prints its path.
- `tds-factory run review --id <id> --axis <axis> --data '<JSON>'` records a project review report tied to the current head and attempt. See the installed `add-project-review` Skill's `references/project-reviews.md` for the report contract and browser artifacts.
- `tds-factory run sweep --id <id> [--term TEXT]...` lists, read-only, every place in the documents that holds a term the Run's diff changed or a `--term` you add, grouped by term with file and line; a hit in a file the Run changed is tagged `changed`, and hits in files marked as replaced come apart. It judges nothing and edits nothing.
- `tds-factory run verdict --id <id> --axis standards|spec|security|infrastructure --value pass|fail|skipped` records one Check axis verdict for the current head; `--carried` keeps an earlier Security or Infrastructure verdict after a text-only Rework (see Check). Infrastructure may be `skipped`, and Spec only on the Fast track, and a `pass` or `skipped` on a worktree with uncommitted changes is refused.
- `tds-factory run follow-up --id <id>` reads the recorded GitHub PR and snapshots current-head CI and unresolved review threads. Actionable feedback immediately starts scoped Rework under the shared four-loop cap and clears all current Evidence; a clean or pending observation remains in Follow-up. At the cap, it retains scope and reports the limit. A merged PR ends Follow-up as Done; closed unmerged or incomplete reads refuse unchanged.
- `tds-factory run rework --id <id>` sends a Run in Check back to Build: it counts the loop (at most 4, or the lower cap in the project config) and clears the verdicts, the Verify result and any accepted decision.
- `tds-factory run sync --id <id>` rebases the Run branch onto the freshly fetched default branch of `origin` in Build or Check. It refuses uncommitted changes, and on a conflict it names the files and leaves the branch unchanged. It clears the Evidence when the head or recorded base changes, without counting a loop.
- `tds-factory run accept --id <id> --data '{"findings":"...","decision":"..."}'` records the user's decision to continue to Finish with a Check that is not clean, for the current head only.
- `tds-factory run complete --id <id>` ends a Run in Finish or Follow-up that has a `pr` link and sets `status` to `done`.
- `tds-factory run clean --id <id> | --all` removes the worktree and local branch of a Run whose recorded PR is merged, from the main checkout only. It keeps the Run record, and leaves a Run that is not done, has an unmerged PR, uncommitted changes, submodule work that exists nowhere else, or branch commits outside the merged PR in place, saying why.
- `tds-factory run stats --id <id> | --all` reports observed Stage time, Reworks and first-pass clean rate. It does not change records.
- `tds-factory run inspect [--id <id>] [--json]` reports records that cannot be read, lock ownership, orphaned, missing, unknown or dirty worktrees, stale Evidence, and project files committed while the Run is still in Define (`stage-skipped`) without changing anything.
- `tds-factory run repair --id <id>` prints a repair proposal; add `--apply` only after reviewing it. It reconciles git and GitHub, preserves dirty worktrees, may reconstruct missing records and only clears a lock whose same-host owner is demonstrably dead. It never clears a lock because of age. Inspect a reported repair coordination lock and resolve it manually.

Evidence is the Verify result and the verdicts, each tied to the head commit it was recorded for. Project review verdicts are also tied to the recorded base. A commit made afterwards makes Evidence stale, and Finish only accepts current Evidence.
