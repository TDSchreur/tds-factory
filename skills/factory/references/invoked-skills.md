# Invoked Skills overrides

Where one of these and an upstream step disagree, follow this file. Each `Overrides "..."` quotes the upstream sentence it replaces.

- **to-spec.** Overrides "Check with the user that these seams match their expectations." Choose the seams yourself. Name the concrete documents in the Documents bullet, as `references/define.md` says. Overrides "then publish it to the project issue tracker." The Spec is a Markdown file in `docs/specs/`; do not publish it as an issue and apply no triage label to it.
- **to-tickets.** Overrides "Ask the user:" and "Iterate until the user approves the breakdown." Publish the breakdown without the quiz; the tracker comes from `docs/agents/issue-tracker.md`. Add the documentation Ticket described in `references/define.md` when the Run is on the Full track and the breakdown has three or more Tickets.
- **implement-spec.** Build runs inline in the Run worktree, on its branch, one commit per Ticket, in dependency order. Overrides "Use an **exploration subagent**" and "Use **implementer subagents**" and "with a **merger subagent**" and "kick off more **implementer subagents**": create no subagents and merge nothing. Overrides "Create the integration branch.": the Run branch is the integration branch, and no Ticket worktrees or extra branches are made. Overrides "open a draft PR": Finish opens the only PR. Overrides "call the Skill tool with `code-review` on the integration branch": no closing review, Check owns it. Overrides "Clean up all **implementer subagent** worktrees.": nothing to clean up. Overrides "If a draft PR exists, mark it ready for review.": Finish owns the PR, and Ticket resolution is left to it through `Closes #N`. The Exit checklist's self-check is inline and is not the closing review: it creates no subagent, does not call `code-review`, and records no verdict or Evidence.
