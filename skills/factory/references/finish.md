# Finish

Invoke `pr` to prepare the pull request. If the project has a PR template at `.github/pull_request_template.md`, `.azuredevops/pull_request_template.md` or `docs/pull_request_template.md`, pass it to `pr` and fill it in, including its Infrastructure checklist from the `infrastructure` verdict and its Documentation checklist from the stale-spec check; otherwise keep the layout `pr` produces. Then Invoke `unslop` on the PR title and the prose of the body, and leave diagrams, diffs, code blocks, Evidence output and the template's bold labels as they are. Save the cleaned draft as plain Markdown in `pr.md` in the Run folder. The description has a "Left open" section, filled from the `check-N.md` of the last Check (axis, severity and basis per item, or "none"; summarise a security item without exploit details or secret values, because the description is public); `finish.md` repeats the list. Finish does not wait on the user for it. When the tracker is GitHub, the PR body lists `Closes #N` for every Ticket; otherwise it lists the Ticket paths and has no `Closes` lines. Push the branch and open the PR. If `pr` is already recorded, push the new head to the same branch and update that PR; do not open a second PR. When the PR is handled, run `tds-factory run complete --id <id>` after setting `pr`. Once the user has the PR merged, `tds-factory run clean --id <id>` from the main checkout removes the Run worktree and branch; never run it from inside the worktree.
