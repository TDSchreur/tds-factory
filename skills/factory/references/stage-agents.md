# Stage agents

`tds-factory install` also installs five Stage agents per Agent target: `factory-define` (Define), `factory-build`, `factory-check` (read-only), `factory-finish` and `factory-follow-up`. Their model choices are the user's to edit; install never overwrites an existing agent file. A project may set a model per Stage in `.factory/config.json`: read the frozen settings with `tds-factory run config --id <id>` and, when `models` names the Stage (or `interactive-check`), pass that model when you dispatch the agent, instead of the one in its file. When the client can dispatch to a named agent, hand the Stage's work to it with the instructions of that Stage; otherwise do the work yourself. You stay the coordinator: you talk to the user (relay Define questions and answers), own the Run record, approvals, Check loops and the push. It also installs `factory-interactive-check` for project reviews requiring app and browser access. After a handoff, say which agent ran, and report plainly when the requested model was unavailable, substituted or cannot be verified; never claim a model was used that you cannot confirm. The baseline `factory-check` agents are read-only and may not run commands: collect the diff and run any validation (such as `bicep build` and `bicep lint`) yourself, and pass the output with the assignment.
