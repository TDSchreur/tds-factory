# One Release per merged change, installed from the latest-release URL

Colleagues used to clone the repository and run `setup.sh`. We now publish a Release on GitHub for every change merged to `master`, and colleagues install it with `npm install -g` from the fixed URL `https://github.com/TDSchreur/tds-factory/releases/latest/download/tds-factory.tgz`. The same command updates. The workflow takes major and minor from `package.json`, uses the next free patch number after the latest tag with that major and minor, and writes that version into the tarball only, so `master` gets no bump commit and nobody bumps a version by hand. We rejected `npm install -g github:TDSchreur/tds-factory` because it installs whatever is on `master` and makes versions pointless, and GitHub Packages because every colleague would need a token. The cost is that the repository has to be public, and that every merge, including a docs-only one, produces a Release.
