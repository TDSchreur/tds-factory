# A Rework may carry over Security and Infrastructure verdicts for text-only changes

Evidence is tied to the code revision it was recorded for, so after every Rework all four Check axes were reviewed again by fresh reviewers, about 110k reviewer tokens per pass. Most Reworks only fix documentation: in the Factory's own Runs, the loops after the first were mostly stale statements in Markdown, which Security and Infrastructure cannot be affected by. [Issue #289](https://github.com/TDSchreur/tds-factory/issues/289) lets those two axes keep their verdict in that case.

`tds-factory run verdict --axis security|infrastructure --value pass|skipped --carried` records a **Carried-over verdict** for the current head. The command, not the coordinator, decides: it refuses unless (1) the axis has an earlier recorded verdict of `pass` or `skipped` (from the Run's verdict history, which a Rework does not clear) with the same value, (2) that earlier head is still an ancestor of the current head, so a rebase by `run sync` disables it, (3) the worktree is clean, and (4) every file changed since that head is a Markdown file outside `skills/` and `agents/`, because those hold instructions that Security reads. The verdict is recorded for the current head and attempt like any other, with `carried_from` naming the head it came from, in the Run record and in the verdict history. Evidence and Finish are unchanged: they see a verdict for the current head. Standards and Spec are never carried, since they read the documents a text-only Rework changes. Reviewers stay fresh, read-only and independent; the previous findings and the rework diff are passed to the axes that are reviewed again.

We considered carrying all four axes, or leaving the decision to the coordinator. Carrying Standards or Spec would hide exactly the stale-text findings that cause most loops, and a decision without a check depends on one agent's judgement, the problem the Blocking finding rule exists to remove. The cost is a small rule to learn: only Security and Infrastructure, only for Markdown-only changes. See [ADR 0013](0013-run-metrics-preserve-observed-history.md) for the verdict history it reads and [GLOSSARY.md](../../GLOSSARY.md) for **Carried-over verdict**.
