# The Run record carries model, last seen and an event log

The Dashboard needs to say which model runs a job, how far it is and whether the agent went quiet ([issue #275](https://github.com/TDSchreur/tds-factory/issues/275)). The Run record gets three kinds of data, all through the Run store ([ADR 0006](0006-run-progress-goes-through-named-transitions.md), [ADR 0012](0012-run-store-is-split-by-seam.md)).

**Model fields.** `requested_model`, `requested_effort` and `observed_model` are plain strings that `run update` accepts, because the agent is the only one that knows its model and effort. Every change of Stage, whether a transition, a Rework or a Follow-up, clears all three and then sets `requested_model` from the frozen project settings for the new Stage when there is one, so a value never outlives the Stage worker it described. `changeRun` does this when it sees the Stage change, so no operation can forget it. The names keep apart what was asked for and what was seen: a requested model is a request, never a confirmation, and only `observed_model` says what an agent reported. We did not read the agent files for the requested model, since the coordinator already passes the configured model when it dispatches and the user may edit the files.

**Last seen.** `last_seen` is set inside `changeRun`, the function every change to an existing Run passes through, not in each operation, so a new operation cannot forget it. `run start` and `run repair --apply` write a record on their own and set it themselves. It differs from `updated` only in intent: `updated` says the record changed, `last_seen` is the sign of life the Dashboard shows.

**Event log.** `events.jsonl` in the Run folder is append-only. The Run store derives Stage changes, Ticket completions, waiting, release, other status changes and Reworks by comparing the record before and after a write, in `changeRun`, again so no operation can forget one. Verify start and finish are appended by `verifyRun`, which runs outside the lock. An append that fails is ignored: the record stays the source of truth and an operation must not fail over its history. The reader skips lines it cannot parse and reports how many, refuses a symlinked log and reads only the end of a large one. We chose a separate file over an array in `run.json` so that the record stays small and a damaged log cannot make a Run unreadable.

Old records without any of this load unchanged and show unknown values. Run metrics ([ADR 0013](0013-run-metrics-preserve-observed-history.md)) are unchanged; the event log is a different, finer record and never feeds a gate or Evidence.
