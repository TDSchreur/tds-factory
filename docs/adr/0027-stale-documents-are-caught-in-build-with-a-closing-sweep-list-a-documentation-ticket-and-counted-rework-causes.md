# Stale documents are caught in Build with a closing Sweep list, a documentation Ticket and counted Rework causes

[ADR 0023](0023-check-loops-are-cut-by-sweep-and-checklist-not-by-gates.md) cut Check loops with a broader Sweep and a sharper Exit checklist, and chose not to add gates. Stale current documents were still the Blocking finding that sent a six-Ticket Run back to Build: the Sweep had listed the documents, but its long output was filtered and truncated, it did not search the command line help, and each Ticket had updated only the documents it remembered.

We keep ADR 0023's rule and add four things that do not gate a transition. `run sweep` ends with a short list of the documents still to read, so a reader who truncates the output still sees the files, and it also searches the command line help and the Dashboard help text. Exit checklist step 2 requires reading the whole output and a Sweep paragraph in `build.md` that names the files changed because of it and the hits judged unaffected. Define names concrete documents in the Spec, and a Full track Run with three or more Tickets gets a last documentation Ticket blocked by the others. `run rework` takes an optional cause from a fixed list, stored in the Run metrics, so `run stats` can count why Runs go back to Build and ADR 0023's success measure can be read by cause.

We did not add a refusal at `run transition --to check` for open Sweep hits: the hits include false positives and a gate would block on noise, as ADR 0023 found. The cause is optional, so older Runs and scripts keep working; a Rework without one counts as unknown, never as another cause. See [the Spec](../specs/stale-documents-in-build.md).
