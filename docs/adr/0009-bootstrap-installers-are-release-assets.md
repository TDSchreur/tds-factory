# Bootstrap installers are Release assets that only call npm and the CLI

> Partly superseded: `install.ps1` no longer supports Windows PowerShell 5.1; see [ADR 0011](0011-install-ps1-supports-powershell-7-only.md).

ADR 0005 records that we removed a setup script and moved colleagues to one `npm install -g` command. We now attach `install.sh` and `install.ps1` to every Release so a new user can run `curl -fsSL .../releases/latest/download/install.sh | sh` or `irm .../install.ps1 | iex`. This is acceptable because the scripts hold no install logic of their own: they check Node and npm, run the same `npm install -g` command as the README and run `tds-factory install`. Everything that can go wrong in an update (version lookup, retries, checksum, `--force`) lives in `tds-factory update`, which is Node code covered by `npm test`, so there is one implementation for every OS instead of a script per shell. `curl | sh` trusts whoever can publish a Release, which is the same trust as the npm URL, and the manual commands stay in the docs for anyone who wants to read before running. We rejected copying a standalone PowerShell updater into the repo because a `.sh` twin would duplicate its logic and neither copy could be tested by `npm test`.
