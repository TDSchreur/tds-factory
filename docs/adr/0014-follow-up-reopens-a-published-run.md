# Follow-up explicitly reopens a published Run without changing Finish or Done

[ADR 0006](0006-run-progress-goes-through-named-transitions.md) gives named operations ownership of Run progress. Follow-up extends that rule as a fifth Stage after Finish. Finish still publishes or updates the Run's pull request, and `run complete` still marks that publication done: Done means the Factory has delivered the current revision for review, not that GitHub has merged it. We keep this contract so existing Runs and callers do not silently change meaning. Follow-up is explicit: `run follow-up` can reopen a done Run in Finish or Follow-up, or continue a running Run there, when it has a recorded pull request.

For an open pull request, Follow-up reads CI on its current head and all unresolved review threads. The PR head must equal the clean Run worktree's head before any scoped Rework is created. A named, persisted snapshot holds failing checks and unresolved review comments as untrusted source material, never executable instructions. Actionable findings send the Run to Build in the same command, incrementing the existing Check loop count and clearing all current Evidence and any Accepted Check. Build addresses that scope, then every applicable Check axis and Verify must produce new Evidence before Finish updates the same PR. The four-Rework cap is shared across Check and Follow-up, never reset by publication; at the cap, Follow-up retains its snapshot and reports the limit instead of starting Build or accepting findings. Historical metrics remain descriptive as in [ADR 0013](0013-run-metrics-preserve-observed-history.md).

When no actionable findings exist, the Run stays in Follow-up while CI is pending or review can still arrive; a later `run follow-up` refreshes the snapshot. The user may end the observation with `run complete`, preserving the existing Done meaning, or abandon the Run. A subsequent explicit Follow-up can reopen Done again. If GitHub reports the PR merged, Follow-up ends as Done without creating Rework or requiring a still-present worktree. Run clean-up remains a separate command with its existing safeguards. A closed, unmerged PR or an unavailable, malformed or incomplete GitHub read refuses without changing the record. There is no background polling, PR merge, comment resolution or CI rerun. This trades automatic waiting until merge for an explicit command and compatibility with already completed Runs. See the [Follow-up Spec](../specs/follow-up-stage.md).
