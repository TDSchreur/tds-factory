# Dashboard: served files test

Diagnosis: #369 fixed a Dashboard that did not load because the module `help.js` was missing from the `ASSETS` allowlist of `src/dashboard.js`. Nothing caught it: the browser tests serve the page from their own stub server, and the asset test in `test/dashboard.test.js` lists the served names by hand, so a new module only fails once someone remembers to add it there. This fix adds a unit test, `test/dashboard-served-assets.test.js`, that works out which files the page loads and asks the real server for each one. It collects the paths from `dashboard/index.html` (the `src` of scripts, the `href` of stylesheets and icons, and the URLs of the import map) and from every relative `import` or `export ... from` in the files of `dashboard/` including `vendor/`, follows them, starts `startDashboard` and checks that each path answers 200 with a content type that matches its extension; it also checks that every `.js` and `.css` file in `dashboard/` (outside `vendor/`) is reached that way, so a module that nothing imports yet is noticed. The test fails on the stylesheet-less state before #369 (`GET /help.js` answered 404) and is proved to do so by removing `/help.js` from `ASSETS` for one run. No change to `src/` or to what the Dashboard does; `docs/dashboard.md` gets a sentence that names the test.
