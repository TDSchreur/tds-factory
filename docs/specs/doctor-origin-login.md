# The git check fails at once when origin needs a login

Fast track. Diagnosis: Git Credential Manager ignores `GIT_TERMINAL_PROMPT=0` and opens its own browser login, so `git ls-remote` in `originDefaultBranch` blocks until its 20 second timeout, and `tds-factory doctor` (and `run start`, which reads the same default branch) reports only `origin did not answer: spawnSync git ETIMEDOUT`. A person who does not see the browser window cannot tell what the Factory waits for. Fix: `originDefaultBranch` runs git with `GCM_INTERACTIVE=never`, so a helper that needs a login fails in about a second and git's own message ("could not read Username… terminal prompts disabled") reaches the report; a real timeout now says `origin did not answer within 20s; check the network, or a credential helper waiting for a login`. The Factory no longer opens a login window itself: with expired credentials `doctor` fails fast and the person logs in with git. One regression test runs `doctor` against a local origin that always asks for credentials, with a credential helper that waits unless `GCM_INTERACTIVE=never`, and asserts a `fail` git check, the message and an answer in under 10 seconds. Out of scope: the later `git fetch` in `fetchOriginDefault`, which only runs after `ls-remote` obtained credentials.
