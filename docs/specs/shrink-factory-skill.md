# Shrink the factory Skill

[GitHub issue #290](https://github.com/TDSchreur/tds-factory/issues/290), Fast track (the user left the track choice to the coordinator for this session), priority work of milestone v0.6.0. `skills/factory/SKILL.md` grew from 14.9 KB to about 40 KB in three days (about 10,000 tokens) and is loaded on every `/factory` call; most of it is needed rarely. The main file keeps what every Run needs, in short: Preflight, the Run record basics, Stage summaries, Waiting, the Invoked Skills contract, Tracks, Define, Build, Check, Finish. The reference text moves, word for word, into files next to the Skill in `references/`, each named where it is needed ("read `references/follow-up.md` before running Follow-up"), the way `add-project-review` already works: the progress command list, the `run.json` schema, the Stage agents, the Exit checklist with the pass after a Rework, the Check details (inline assignment, Infrastructure, project reviews, the Blocking finding rules, carried-over verdicts, Clean) and Follow-up. `install` and `sync` ship the reference files with the Skill and `tds-factory doctor` checks that the installed Skill has them. The tests that pin the Skill text read the main file together with its references; no rule of the Flow changes and the eval scenarios are unchanged. On the Fast track `build.md` is three lines, and the story trace and the security table are needed only when a trust boundary is touched. Out of scope: changing any rule or command, and the Stage agents' own files.
