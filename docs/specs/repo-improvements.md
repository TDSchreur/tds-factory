# Repo improvements: compact docs and deduplicated tests

## Problem Statement

A day of features left the repo with 27 shipped specs (a third of its bytes), a README that restates the `factory` Skill, a Skill that repeats its own rules, glossary entries that read like specs, and dashboard tests that re-test Run store rules. Readers and agents load more text than they need, and the copies drift.

## Solution

Archive shipped Specs, cut the README to an overview that links to the Skill, state each Skill rule once, shorten glossary entries, and leave storage rules to the Run store tests. No behaviour changes.

## User Stories

1. As a reader, I want only in-flight Specs in `docs/specs/`, so that I see current work at a glance.
2. As a reader, I want shipped Specs still available in an archive, so that old Run records' Spec links keep pointing somewhere useful.
3. As a newcomer, I want the README to say what the Factory is and how to set it up, so that I am not reading the Flow rules twice.
4. As a newcomer, I want the README to link to the `factory` Skill for the Flow rules, so that there is one source of truth.
5. As a maintainer, I want the per-stage model table to live in the issue that tracks it, so that the README describes only what ships.
6. As an agent, I want the Clean rule stated once in the Skill, so that I cannot read two versions.
7. As an agent, I want the waiting protocol stated once in the Skill, so that I follow one set of steps.
8. As an agent, I want every rule the Skill tests guard to remain, so that tightening loses no behaviour.
9. As a reader, I want glossary entries of one or two sentences, so that the glossary defines terms instead of specifying behaviour.
10. As a maintainer, I want each storage rule tested once, in the Run store tests, so that a rule change touches one test.
11. As a maintainer, I want the Dashboard tests to keep checking HTTP routing and status codes, so that the HTTP layer stays covered.

## Implementation Decisions

- Every shipped Spec moves, unchanged, into an archive folder under the Specs folder. This Spec stays out of the archive until it ships.
- The README keeps the Flow diagram, setup, install options, the Dashboard route table, Skills sources and limitations. The long Flow prose becomes a short overview plus a link to the `factory` Skill. The phrases the README test checks stay.
- The model table moves to a comment on issue #32; the README keeps one line pointing there.
- The `sync` rejection rules shrink to one sentence.
- In the `factory` Skill, the Clean rule is defined once in Check; the waiting protocol is defined once in "Waiting on the user" and referenced from "Run record". All phrases pinned by the Skill tests stay.
- The Dashboard, Clean and Run store glossary entries shrink to one or two sentences.
- Dashboard tests that assert storage rules already covered by Run store tests are removed or reduced to the HTTP status they map to.

## Testing Decisions

- The seam is the existing `npm test` suite; no new seams.
- Doc tickets are verified by the existing Skill and README tests staying green.
- The test ticket must keep total coverage of each storage rule: every removed Dashboard assertion has a matching Run store test.

## Out of Scope

- Editing vendored Skills (they are regenerated by `sync`).
- Automating Spec archiving in the `factory` Skill.
- Rewriting Skill tests to stop pinning prose.

## Further Notes

Housekeeping outside the repo (re-running `tds-factory install`, removing empty `.aws/`, `.codex/`, `.agents/` folders, deleting the untracked `improvements.md`) is done by the Run directly, without Tickets.
