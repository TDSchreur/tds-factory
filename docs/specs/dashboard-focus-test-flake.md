# Dashboard: focus ring test waits for the detail focus

Diagnosis: the browser check of #373 failed once in `a hovered or selected card keeps its inner focus ring` (`test/dashboard-a11y-browser.test.js`): the selected and focused card showed the brand selection ring without the focus ring, while the same job had passed on main minutes before and the test passes locally. Selecting a card opens the Run detail, and the detail moves the focus to its heading in an effect that runs after the next frame (`Detail` in `dashboard/components.js`); the test focused the card as soon as the `selected` class appeared, so on a slow runner that effect can run after the test's `focus()` and take the focus away, and the card is then read while it is no longer focused. The fix is in the test only: after the click it waits until the detail heading has the focus, then focuses the card, asserts that the card matches `.selected:focus-visible` and reads the ring. No change to `src/` or `dashboard/`, and the test still fails on the stylesheet before #360.
