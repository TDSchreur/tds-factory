# Dashboard: focus ring test waits for the detail focus

Diagnosis: the browser check of #373 failed once in `a hovered or selected card keeps its inner focus ring` (`test/dashboard-a11y-browser.test.js`): the selected and focused card showed the brand selection ring without the focus ring, while the same job had passed on main minutes before and the test passes locally. The failing value was exactly the brand selection ring, the value before the focus ring is applied. Two timing dependencies of the test can produce it on a slow runner, and the failure could not be reproduced locally to tell which: (1) selecting a card opens the Run detail, which moves the focus to its heading in an effect that runs after the next frame (`Detail` in `dashboard/components.js`), so it can run after the test's `focus()` and take the focus from the card; (2) the test emulates `prefers-reduced-motion` so that no transition is running, but it did not wait until the emulation had taken effect, and a box-shadow transition that has just started still reads its old value. The fix is in the test only and removes both: every test of the file that emulates reduced motion to read a colour or a shadow waits until the emulation has taken effect (reduced motion matches and a button's transition duration is 0s), and in the focus test, after the click it waits until the detail heading has the focus, then focuses the card, asserts that the card matches `.selected:focus-visible` and reads the ring. No change to `src/` or `dashboard/`, and the test still fails on the stylesheet before #360.
