# PR provider seam

[GitHub issue #276](https://github.com/TDSchreur/tds-factory/issues/276), Fast track (the user left the track choice to the coordinator for this session), priority-adjacent work of milestone v0.6.0 and the prerequisite for Azure DevOps PR support. The Dashboard, Run clean-up, Follow-up and Run repair each call `gh` directly. Every call moves into one deep module, the PR provider: `src/pr-provider.js` resolves the adapter for a PR link or a git remote, and `src/pr-github.js` is the only adapter and the only file that runs `gh`. Behavior is identical: no CLI output, `run.json` shape or Dashboard API changes, the callers keep their own handling of an unreadable PR and their injection points for tests, and the existing tests pass unchanged. New modules take the project directory as a parameter, with no single-repository assumption. The design is recorded in ADR 0020, the glossary gets **PR provider**, and `docs/development.md` lists the modules. Out of scope: an Azure DevOps adapter, richer PR status (milestone 2), and any change in what the Dashboard shows.
