# Honour CLAUDE_CONFIG_DIR

Claude Code reads its user-level skills, agents and session logs from the folder named by the `CLAUDE_CONFIG_DIR` environment variable, and from `~/.claude` only when that variable is unset. The Factory always uses `~/.claude`, so with `CLAUDE_CONFIG_DIR` set, `tds-factory install` writes the skills and Stage agents where Claude Code never looks, `/factory` is missing in the session, `doctor` still reports the claude target as usable because it checks the same wrong folder, project reviews resolve user-level skills from the wrong folder, and the token Usage of Claude sessions is not found. Fix: one helper resolves the Claude user folder as `CLAUDE_CONFIG_DIR` when it is set to a non-empty value (resolved to an absolute path) and `~/.claude` otherwise, and every user-level Claude path uses it: the global skills and agents folders of `install` and `scripts/dev-install.js`, the claude skills and agents checks of `doctor` (including the Claude folders it counts for Copilot), the user-level skill lookup of project reviews, and the `projects` folder `usage-claude.js` reads. Project installs (`install --project`, `.claude/skills` in the project) and the Codex and Copilot folders do not change. Documents: `docs/install.md`, `docs/usage.md` (doctor section), `docs/development.md` and a changelog fragment under Fixed. Out of scope: `CODEX_HOME` and other agents' config variables.

Since [install destination selection](install-destination-selection-integration.md), `CLAUDE_CONFIG_DIR` names one candidate Claude destination that the user chooses; it is no longer installed into by default.
