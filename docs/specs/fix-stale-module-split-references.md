# Fix stale references after the Dashboard and PR adapter module splits

PR #455 split `src/dashboard.js` into the route table, handlers, PR views and `src/dashboard-view.js`, and moved the shared runner of the PR adapters into `src/pr-exec.js`, but left some references behind. This change corrects them without changing behaviour. The comments at the top of `dashboard/model.js` name `src/dashboard-view.js` as the home of `interpretRun` and of the declaration that it returns `RunView` (`src/dashboard.js` only re-exports it); a repo-wide search for `src/dashboard.js` finds no other comment, JSDoc or current document that names it for code that moved. ADR 0020 gets a short paragraph saying that `src/pr-exec.js` holds the runner, the sync wrapper, the reason error and the remote helper that both adapters share, names no command, and that `gh` and `az` still run only in their own adapters. The explicit `any` in `Generator<Step, T, any>` in `src/git.js` and in `EventLog.events` in `src/run-events.js` either gets a precise type or a one-line reason, as `docs/development.md` and ADR 0029 ask. Historical Specs that name moved code are left as they are, because no canonical document links them. A changelog fragment records the ADR change. Testing: the Verify command and `npm run check` pass; no test changes are needed.
