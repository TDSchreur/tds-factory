# Evidence invalidation in one place

Fast track, issue #300. Current Evidence (the Check verdicts, `verify`, `reviewed`, `accepted` and `project_results`) is cleared by three paths that each keep their own copy of the field list: Run sync (when the head or recorded base changes) and Check Rework in `src/run-lifecycle.js`, and Follow-up Rework in `src/run-follow-up.js`. Move the rule into one function in `src/evidence.js`, next to the Evidence rules that read those fields, and call it from all three paths, so a new Evidence field is added in one place and no transition can keep stale Evidence. Behavior does not change: an unchanged sync retains Evidence, a changed head or base clears it, and Reworks clear it so it cannot authorize Finish, while historical Run metrics, the observed Check history and every other Run record field stay intact (ADR 0013). The single Run store interface and the named transitions of ADRs 0006 and 0012 stay, and no new public adapter is added. Tests exercise sync (changed and unchanged), Check Rework and Follow-up Rework through the Run store, check that Finish refuses after each, and check that metrics and unrelated fields survive.
