# Static checks in the Exit checklist

Fast track, process change. PR #320 passed `npm test`, the Run's Verify command, and then failed lint, because `npm test` does not run ESLint and nothing in the Build or Check steps asked for it; the user saw the errors after the PR was open. The Exit checklist in `skills/factory/references/exit-checklist.md` gets a new first step, "Static checks": run the lint, typecheck and format-check commands the project has (the scripts in `package.json` or the commands its conventions file lists), fix every failure and run them again, because CI runs them and a failure there is a failure the Run could have caught locally. The step names those commands under "Not run" in `build.md` when they cannot run in the environment, and a project with none skips it. The Factory's own `AGENTS.md` Commands section lists `npm run lint`, `npm run typecheck` and `npm run format:check` next to Verify, so a Run in this repo knows them. The Exit checklist already runs again after every Rework, so the checks also run before each Rework commit. No code, command or schema changes. The step also asks for a linter for each kind of file the diff changes (for example `shellcheck` for a shell script), and the `AGENTS.md` line adds `shellcheck scripts/install.sh`, `npm run test:browser` and `npm run test:package` with the change that calls for each; it also lists `actionlint` and PSScriptAnalyzer for workflow and `install.ps1` changes.
