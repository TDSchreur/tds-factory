# The PR status shows "no conflicts" in the neutral colour

Fast track. Diagnosis: the Dashboard marks a PR status line as an alert when it starts with `Checks: failing` or `Merge: conflicts`. The test used the pattern `/^Checks: failing|conflicts/`, whose second alternative was not anchored and also matched `Merge: no conflicts`, so a mergeable pull request looked broken. The only line the old pattern got wrong was that one; the model sends no other line that contains the word. The fix anchors the alert pattern to the start of the two lines that are problems. A browser test opens a mergeable pull request with passing checks and requires that none of its status lines carries the alert class and that the "no conflicts" line has the colour of the neutral lines, and that a conflicting pull request still shows its merge line as an alert.
