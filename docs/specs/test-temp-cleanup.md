# Tests remove their temp folders

[GitHub issue #280](https://github.com/TDSchreur/tds-factory/issues/280), Fast track, milestone v0.6.0. Diagnosis: nothing removes the folders the tests create. One run of the unit tests (455 tests) leaves 485 folders and about 32,000 inodes in the temp directory (261 `git-repo-*`, 44 `doctor-home-*`, 31 `tds-sync-*`, 27 `git-repo-linked-*` and many more from about 25 test files, the package and dev-install scripts and the eval fixture). On a tmpfs `/tmp` that is about 125 runs from running out of inodes, after which shell tools cannot start and tests fail at random. Fix: every npm script that runs tests or evals (`test`, `test:unit`, `test:browser`, `test:package`, `eval`) goes through one runner script that gives the run its own temporary directory (`TMPDIR`, `TMP` and `TEMP` point at it), runs the command and removes the directory when the command ends or is interrupted, so nothing a run creates outlives it. The shared test helper that makes git repositories also removes its folders when its test process exits, so a run is bounded while it runs too. One test proves that the runner removes what a leaking test creates and passes the exit code on, and one test pins that the five scripts use the runner. `AGENTS.md` and `docs/development.md` say how tests are run. Out of scope: editing every test to clean up after itself.
