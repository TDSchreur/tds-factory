# Fast Verify after each Ticket, full Verify before Check

[GitHub issue #288](https://github.com/TDSchreur/tds-factory/issues/288), Fast track (the user left the track choice to the coordinator for this session), priority work of milestone v0.6.0. `run verify` runs the full `npm test` (about 65 s) after every Ticket, after `run sync` and after every Rework: 6 to 10 times per Run, 6 to 11 minutes of waiting. A project can now give an optional `Verify-fast:` line under `## Commands`. Preflight records it in a new optional field `fast_commands` of the Run (set by `run start` only, empty or absent when there is none). `tds-factory run verify --id ID --fast` runs it in the Run worktree, keeps its output in `verify-fast.log`, prints the result and records nothing in the Run: a fast Verify is quick feedback and never Evidence, and it refuses with a message naming the full Verify when the Run has no fast command. Build runs it after each Ticket when the Run has one; the full Verify still runs after the last Ticket, after `run sync` and before every Check pass, so Evidence, the Check gate and Finish are unchanged. `tds-factory doctor` reports the line as a shared check `verify-fast` (pass when absent, fail when unusable, which does not stop a Run), this repository's `AGENTS.md` sets it to the unit tests (`npm run test:unit`), and the Skill, the glossary (**Fast verify command**), the install guide and the tests say so. Out of scope: skipping parts of the full Verify, recording fast results, and changing the Evidence rules.
