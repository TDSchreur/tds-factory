# Override minimatch to a patched release

Dependabot alert #1 flags `minimatch` below 11.0.1 for a denial of service through globparts amplification. The only path to it is the development toolchain: `eslint@10.14.0` and `@eslint/config-array@0.23.5` depend on `minimatch ^10.2.x`, and `tds-factory` has no runtime dependencies, so nothing vulnerable ships in the package. Upstream ESLint has no release that depends on minimatch 11, so `package.json` gains an npm `overrides` entry that pins `minimatch` to `^11.0.1`, and `package-lock.json` is regenerated so that no minimatch below 11.0.1 remains. `npm run lint` and the rest of `npm run check` keep passing with minimatch 11, and a `Security` changelog fragment records the change. Remove the override once ESLint depends on minimatch 11 itself.
