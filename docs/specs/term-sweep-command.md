# Term sweep as a command

_Extended by [Reduce the number of Check loops](reduce-check-loops.md): the Sweep also lists stale numbers, moved headings, lists and claims._

[GitHub issue #287](https://github.com/TDSchreur/tds-factory/issues/287), Fast track (the user left the track choice to the coordinator for this session), priority work of milestone v0.6.0. The Build Exit checklist's term sweep is done by the agent with ad hoc searches, so it misses text that uses other words, and a fresh Standards reviewer then finds the stale statement one pass later; stale text is the most common Standards failure (it was again in the Doctor, Blocking finding and fast Verify Runs). `tds-factory run sweep --id ID [--term TEXT]...` is a read-only command: it takes the terms changed in the Run's diff against its base (backticked terms, `--flags`, quoted phrases, snake_case and camelCase identifiers, at most 25, most frequent first) plus each `--term`, searches README, CONTRIBUTING, GLOSSARY, AGENTS, CLAUDE, SECURITY, `docs/`, the Specs, the ADRs, the Skills, the agents and the changelog fragments (Markdown and TOML, regular files under 1 MiB, never links, never `node_modules`, `.git`, `.factory` or vendored code), and prints every hit with file and line, grouped by term, case-insensitively. A hit in a file the Run changed is tagged `changed`, and hits in a file marked as replaced by a newer Spec (a line near its top that starts with `_` or `>` and says it was replaced, changed or superseded by something) or in `docs/specs/archive/` are listed in their own group, so the reader can tell a stale statement in a current document from history. Output is plain text with control characters, tabs and newlines stripped, also from file names, and bounded: at most 40 hits per term and 250 in total, lines cut to 160 characters, with a count of what was left out; a term with more than 100 hits is too common to be useful and is reported by count only, to be replaced by a narrower `--term`. The Exit checklist in the `factory` Skill (step 1) uses it, and the Check inline assignment passes its output to the Standards reviewer. The glossary gets **Term sweep**, tests cover a changed identifier, a synonym given with `--term`, the replaced-by marker, the changed tag and the size bound, and a changelog fragment is added. Out of scope: judging whether a hit is stale, editing files, and searching code.
