# Recommend the Fast track by criteria

[GitHub issue #291](https://github.com/TDSchreur/tds-factory/issues/291), Fast track (the user left the track choice to the coordinator for this session), priority work of milestone v0.6.0. The Fast track is chosen only when the user names it or Define recommends it, and the recommendation is not consistent for small work: both Fast track Runs so far needed 0 Check loops against 1.06 on average. Define recommends the Fast track whenever the work meets any stated criterion: it is a bug fix; it is a documentation or test-title change; or its expected diff is at most about five files with no new public interface, schema or dependency. The recommendation names the criterion it meets, so the user can confirm or refuse with a reason. The user still confirms and Define never applies the track silently ([ADR 0015](../adr/0015-fast-track-is-chosen-explicitly-and-keeps-the-check-gate.md) stays). The criteria are listed in the Tracks and Define sections of `skills/factory/SKILL.md` and in `docs/usage.md` and the README, and a test pins the text. Out of scope: choosing the track without asking, changing what the Fast track does, and the Check rules.
